## Feature workflow

New feature: create new branch first, every time.
Before code: write test case first (for new feature).
Test suite must cover old feature + new feature both, confirm no break either side.
Test pass → merge to main branch.

- **Wheel zoom console error.** React's JSX `onWheel` is attached passively by the framework, so `e.preventDefault()` inside it threw `Unable to preventDefault inside passive event listener invocation` instead of blocking page scroll. Fixed with a native `viewportRef.current.addEventListener("wheel", ..., { passive: false })` in a `useEffect`, `zoomAt` accessed via a ref (updated in its own effect, not written during render — assigning `ref.current` mid-render is now an `eslint-plugin-react-hooks` (`react-hooks/refs`) lint error) so the listener isn't re-attached every render.
- **Images didn't move with their frame.** `FrameItem`'s drag handler computes frame membership (what rides along when the frame is dragged) for notes/shapes/texts/arrows — but never for images, because F1 added the `images` Y.Map container after this membership logic was written and nobody came back to wire it in. Added `allImages` prop + a membership loop, same pattern as the other four containers.
- **PDF export did nothing on click.** Root cause took a live browser session to find (static reading of `runExport`/`exportToPdf`/`fitToPage` looked entirely correct): `.topbar` deliberately sets `pointer-events: none` (so clicks pass through its empty chrome to the canvas below) and re-enables it per-element via `.tbGroup`/`.shareBtn`. The Export dropdown menu is a plain unclassed `<div>` — it inherited `none` and was never given it back, so every click on "Whole board"/"This frame"/"Select area" silently fell through to whatever was underneath instead of reaching the button. One line (`pointerEvents: "auto"` on that div) fixed it.
- **`ElementToolbar` (shape/text styling) layout.** Was one `flex-wrap: wrap` row; a wrapping flex container's auto-width sizing is based on its widest *single item*, not the sum of its content, so the container shrank far below what the sizing/align row actually needed and every group reflowed unpredictably depending on which optional groups (color/shape/text-color) were present — the delete button routinely ended up alone on a dangling last line with a large gap in front of it. Restructured into explicit `.ftRow` groups (sizing+align / fill color / shape stroke+fill / B-I-U+text-color+delete), each `flex-wrap: nowrap` at desktop widths (`.fontToolbar` max-width raised 420→460px, enough for the widest row), with per-row overflow-x scroll only reinstated under the existing 720px phone breakpoint.
- **Image tool gave no feedback when signed out.** Clicking it while signed out did nothing visible at all — same button styling as every enabled tool, no click feedback, only a hover `title` explained why (easy to miss, felt like the button was just broken). Added a dimmed visual state (new `.toolDimmed`) plus a one-shot `window.alert` on click, matching the existing alert-on-failure pattern in `onImageFileSelected`.
- Found and fixed a pre-existing `eslint-plugin-react-hooks` violation while touching the wheel handler (`react-hooks/refs`: `ref.current = x` during render, not inside an effect/handler) — not new, but the wheel fix's first draft would have added a second instance if not caught by relint.

Review findings fixed at merge (not by the authoring agent):
- F2 tried `display: flex` on a `<foreignObject>` to bottom-center `ConnectorToolbar`. Flexbox on a `foreignObject` isn't reliably honoured across engines (it's an SVG viewport-establishing element, not dependably a CSS flex container), and the same commit had dropped the `margin: 0 auto` that was doing the job — so if ignored, the toolbar was misaligned at *every* zoom, including 1. Replaced with a `position: relative` wrapper + `position: absolute; left: 50%; bottom: 0`, ordinary CSS every engine agrees on.
- F5 made `.flabel` a flex container, but it's `contentEditable`; inside a flex container its text nodes become anonymous flex items and caret/empty-state handling gets unreliable. Reverted to block layout with `line-height` doing the vertical centering.
- F6 shipped `TEXT_COLORS` as six fixed dark hexes. The agent's own analysis was right that no single fixed hex clears 4.5:1 against both themes (light bg needs luminance ≤ ~0.18, this app's dark bg needs ≥ ~0.26), but the conclusion — ship the light-theme-only set — leaves dark mode, a shipped v1 feature, with near-invisible text. Fixed the way `--ink` already solves it: each entry is a light/dark pair behind new per-theme `--text-N` custom properties, with `--text-N-fixed` (never flipped) used on sticky notes, whose pastel background is theme-invariant. Contrast is asserted for both variants against both themes' panel and canvas backgrounds.
- F1's `POST /api/uploads` took its MIME from `File.type` (client-supplied, trivially spoofed) and used `readImageDimensions` only to fill in width/height, never to reject — so the allowlist filtered only what a well-behaved client *declared*, and any signed-in user could store arbitrary bytes in the public bucket under an image content-type. Added `bytesMatchMime()` and a 415 on mismatch (the PNG/GIF/JPEG readers already return null on a bad signature so they double as the check; WebP gets a direct `RIFF....WEBP` header match).
